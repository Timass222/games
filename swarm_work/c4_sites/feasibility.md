# ChatGPT Sites для многокомандного демо

ChatGPT Sites — выбранный основной вариант. В текущей сессии присутствуют инструменты регистрации, публикации, управления доступом и чтения состояния базы Sites. В репозитории игровой код и конфигурация хостинга ещё отсутствуют. Локальная документация установленного Sites описывает серверный Worker и постоянное хранилище D1. Публичный Site можно открывать без входа в ChatGPT, если публичный доступ доступен аккаунту. Закрытый сайт требует соответствующего доступа. Работа общей игры, разрешения конкретного аккаунта и доступ со сторонних сетей требуют практической проверки. [Справка OpenAI](https://help.openai.com/en/articles/20001339-creating-and-using-chatgpt-sites)

## Макет технической проверки

1. Две вымышленные команды и ведущий, один цикл, один публичный проект и по одной закрытой карточке. Ведущий создаёт общую партию. Ноутбук лидера и телефон посла подключаются к ней с разными ролями. Командные сессии хранятся на сервере. Для публичного входа можно использовать отдельные коды команд и ролей внутри игры. Ведущий получает собственный доступ.
2. Единое серверное состояние хранит ресурсы, фазу, сделки и ревизию. Клиенты периодически получают свою версию состояния. В каждой операции отдельно проверяются партия, роль, фаза и право на сведения. Скрытые сведения не входят в ответ сервера для чужой команды. Перезагрузка телефона восстанавливает подтверждённое состояние.
3. Два посла подтверждают обмен. При одновременном подтверждении сделок на один остаток вторая не может забрать уже зарезервированный ресурс. Подтверждение по сетевому повтору не списывает ресурс повторно. Проверить это на общей базе, где возможны параллельные запросы. Выбрать транзакцию или условную запись версии одного состояния в зависимости от проверенных возможностей хранения.
4. Проверить доступ из разных сетей на ноутбуке и телефоне. При общем интернете обе сессии должны видеть одну партию. После теста на двух устройствах повторить с приближённой нагрузкой в 13 активных экранов: шесть ноутбуков, шесть телефонов и устройство ведущего.
5. Переключить фазу и убедиться, что все получают один номер цикла и видят только свои данные. Операция посла из закончившейся фазы получает понятный отказ. Проверить разрыв соединения и повторное подключение, затем сохранить измерения и оставшиеся риски.

Отдельные метки результатов для отчёта: **подтверждено локальной документацией**, **проверено в размещённом приложении**, **нужна проверка на месте**. Текущий результат относится к первой метке. Разграничение доступа, конкурентные записи и работа из разных сетей остаются сценариями для реализации и проверки.
