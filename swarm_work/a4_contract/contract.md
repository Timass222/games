# Формат материалов для первого плейтеста

Источники правил — [план механик](../../GAME_MECHANICS_PLAN.md) и [задание рою](../../SWARM_BRIEF.md). Этот документ задаёт общий формат и предлагает рабочие допущения для сравнения и прогона. Статус допущений в явном виде сохраняется в итоговом наборе.

## Состав материалов

| Объект | Обязательные данные | Дополнительные данные |
| --- | --- | --- |
| Фракция | Стабильный ID и название, три стартовых запаса, базовый доход по каждому виду, благополучие или правило Ордена, общедоступный профиль и закрытые вводные | Мотивация, подсказка к переговорам |
| Проект | ID, название, источник идеи, доступ и получатели, цикл или условие открытия, тройка целых цен за единицу, число одинаковых единиц, условия и эффекты завершения | Дедлайн с явным последствием, зависимости, временные или постоянные эффекты, метка представительства |
| Этап башни | Те же поля, основной номер этапа, минимальный цикл и предыдущий этап | Дополнительный этап для компромиссной площадки |
| Площадка | ID, описание, эффекты старта по затронутым командам, изменение цепочки башни, обозначение заранее известного компромисса | Сюжетные связи и будущие условные события |
| Событие | ID, цикл проверки, условие по состоянию на начало цикла, объявление, точное изменение и момент эффекта | Известные последствия бездействия, ветки, новые карточки и общий узел |
| Сделка | Цикл, стороны, согласованные обязательства, явное подтверждение каждой стороны, состояние резерва, исполнение | Целевой проект и запрет вклада в текущем цикле. Будущие обещания можно хранить отдельно как заметки |

Цена пишется в порядке **А / Б / Р**, где Р — рабочие действия. Целая единица оплачивается целиком. Команды могут оплатить её общим вкладом из целых ресурсов. Проекты с несколькими единицами сохраняют число уже оплаченных единиц. Для каждой карточки показать, кто и зачем платит, какая у сторон альтернатива, как эффект создаёт следующее решение. Положительные и отрицательные значения по затронутым фракциям публикуются на публичной карточке до вложений. Указывать источник как «Мелисса Пxx», «S05» или «авторская идея». Статус каждого нового числа и варианта — предложение для прогона.

Агенты могут использовать свои префиксы ID. Интегратор выдаёт итоговые ID, связывает ссылки и фиксирует одну версию цены и эффекта. Для текста игрока отдельно хранить легенду и точное правило. Скрытые карточки, цель Ордена, точные чужие запасы и приватные сделки остаются в соответствующей команде или состоянии ведущего. Публичный игрок получает только то, что ему положено видеть.

## Открытые решения и варианты для первой сборки

| Вопрос | Предложение для прогона | Другая возможность и её цена |
| --- | --- | --- |
| Как засчитать участие в ресурсном объекте | Записывать прямых вкладчиков, доступ получают команды, оплатившие не меньше одной целой единицы в сумме по согласованному вкладу либо явно участвующие в её совместной оплате по указанному минимуму. Для первого прогона на каждой карточке просто определить условие доступа; трансфер другому плательщику сам по себе участия не даёт | Раздавать доход пропорционально вкладу. Это усложняет учёт и добавляет дроби или остатки |
| Когда доступна полученная передача | После взаимного подтверждения резервировать исходящие ресурсы. При закрытии переговоров исполнить подтверждённые передачи, затем считать итоговые вложения из обновлённых остатков. Не обещать в текущей фазе ещё не полученные ресурсы | Сразу проводить каждый подтверждённый обмен. Даёт послам больше гибкости, требует проверки цепочек и одновременных подтверждений |
| Как обеспечить запрет вложения по сделке | Записать тройку «команда, проект, цикл», запретить противоречащие вклады и взаимно несовместимые обязательства. Прежде чем принять новое подтверждение, проверить остаток и имеющиеся запреты | Разбирать конфликты у ведущего. Это съест время и даст разные ответы на одинаковые ситуации |
| Как считать представительство | Оплата проекта создаёт публичную метку. Со следующего цикла перевести Ордену указанное число Р из поступивших действий партнёра. Перевод ограничен доступным объёмом, без долга или отрицательного остатка. Выбрать цену и ограничение повторных меток перед прогоном | Списывать материалы там, где это важно по сюжету. Потребуется определить порядок списания, если несколько эффектов претендуют на один запас |
| Когда видны последствия личного проекта Ордена | Завершение записать в конце цикла. В начале следующего объявить внешнее изменение и применить его к соответствующим открытому проекту или доходу. Источник эффекта можно оставить скрытым по карточке, исполнение известно ведущему | Показывать сразу по итогам хода вместе с другими результатами. Подходит, если это не меняет уже завершившиеся решения |
| Что сохраняется при изменении цены | Сохранить число готовых единиц. Новая цена действует лишь на последующие единицы, открытая карточка обновляется в начале цикла | Изменить общее число требуемых единиц при сохранении готовых. Более резкое изменение, которое уместно для отдельного явно описанного случая |
| Что происходит при пропуске срока | Карточка закрывается, вложенная работа не возвращается, последствия только по самой карточке. При необходимости новым проектом дать отдельный путь исправления | Частичный возврат материалов, если об этом заранее сказано. Добавляет учёт источника каждого вклада |
| Что делает ресурсный человек | Пока посол договаривается, анализирует запасы и предлагает лидеру два выполнимых распределения, объясняя последствия. Лидер принимает и вводит решение | Отдельный механический допуск или кнопка остаются вопросом после наблюдения на плейтесте |

Минимальный итоговый журнал хранит номер цикла и фазу, выбранную площадку, доступные проекты и их прогресс, команды-вкладчики, ресурсы и резервы, сделки, благополучие, представительства, будущие эффекты и причины их появления. При проверке одного прогона отдельно сверять начало цикла, закрытие переговоров и итог после оплаты. У каждого разового эффекта одно применение. Неиспользованные Р сгорают после цикла, материалы переходят.

## Контрольная цепочка

Открытие карточки → видимые условия → предложение команды или совместный вклад → проверка цены и резерва → целая единица → завершение → результат → новые стимулы следующего цикла. Простого ресурса или красивого имени для участия недостаточно: показать, почему сторона может и согласиться, и отказаться. Сравнивать варианты по всей цепочке.
