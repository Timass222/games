# Цифровой прототип «Вавилонская башня»

Локальная репетиция сценария «Высокая вода». Ведущий объявляет события и управляет фазами, лидер голосует и вносит вклады, посол заключает сделки. При ротации игроки обмениваются кодами ролей. При обычном запуске коды выдаёт ведущий.

Из корня репозитория в PowerShell:

```powershell
node site_app/server.mjs
```

Откройте [локальную игру](http://127.0.0.1:8796/) и введите код ведущего из терминала. Для нескольких ролей на одном компьютере используйте разные вкладки. Для учебного просмотра только на этом устройстве можно перед запуском установить `$env:DEMO_PREVIEW='1'`. Эта опция показывает коды ролей на экране входа. На время командной репетиции уберите её через `Remove-Item Env:DEMO_PREVIEW -ErrorAction SilentlyContinue`.

Локальный сервер держит одну партию в памяти. Перезапуск создаёт новую партию и новые коды.

## Версия в ChatGPT Sites

[Вавилонская башня на Sites](https://babel-tower.timapochta63.chatgpt.site/#game-entry) хранит общую партию в базе и работает для устройств с доступом к сайту через интернет. Опубликованная партия начинается с голосования и формата 4×3.

1. Владелец входит в Sites своим ChatGPT-аккаунтом и нажимает «Войти как ведущий».
2. До голосования ведущий при необходимости меняет формат на 4×2 через «Выбрать формат». Затем нажимает «Показать коды команд» и передаёт участникам ссылку и коды. В 4×3 ресурсный менеджер работает рядом с лидером за его экраном.
3. Участники открывают ссылку и вводят код своей роли. После финала ведущий может создать новую партию. Она получает новые коды.

Доступ к ссылке задаётся в настройках Sites. Игровые коды управляют тем, что участник видит и может делать внутри партии. [Облачный адаптер и сборка](../sites/babel-tower/README.md)

## Запуск на четыре команды

Участвуют Строители, Жители, Торговцы и Орден. В обоих форматах те же [33 карточки демо](../swarm_work/playtest/demo_4_teams.md), шесть игровых циклов и порог в три голоса из четырёх при выборе площадки. Ведущий считается отдельно.

| `GAME_FORMAT` | Игроков | Кто за что отвечает |
| --- | --- | --- |
| `4x3` | 12 | Посол ведёт сделки. Ресурсный менеджер проверяет запасы и предлагает раскладку за экраном лидера. Лидер фиксирует решения. |
| `4x2` | 8 | Посол ведёт сделки. Лидер считает запасы, выбирает раскладку и оформляет вклады. После третьего цикла они меняются ролями. |
| `6x3` | Исходный режим | Запускается по умолчанию. |

Чтобы запустить запасной формат рядом с базовой игрой, откройте отдельный PowerShell:

```powershell
$env:GAME_FORMAT='4x2'
$env:GAME_EXPERIMENT='baseline'
$env:GAME_PORT='8799'
node site_app/server.mjs
```

Адрес на этом компьютере — [формат 4×2](http://127.0.0.1:8799/). Для 4×3 выберите `GAME_FORMAT='4x3'` и отдельный порт, например `8798`. Ведущий получает по два кода входа на фракцию и один для себя. Полный прогон обоих форматов проверяет `node site_app/check-four.mjs`.

### Игроки подключаются с телефонов

Подключите ноутбук ведущего и телефоны к одной сети. В отдельном PowerShell задайте нужный формат и свободный порт:

```powershell
$env:GAME_FORMAT='4x3'
$env:GAME_EXPERIMENT='baseline'
$env:GAME_HOST='0.0.0.0'
$env:GAME_PORT='8810'
Remove-Item Env:DEMO_PREVIEW -ErrorAction SilentlyContinue
node site_app/server.mjs
```

Для 8 игроков задайте `4x2`. Ведущий открывает адрес ноутбука в этой сети на порту `8810` и выдаёт коды входа. `127.0.0.1` открывает игру только на самом ноутбуке. На площадке заранее войдите с телефона под одной из командных ролей. [План проведения](../swarm_work/playtest/live_runbook.md)

## Проведение

1. Лидеры выбирают площадку. Ведущий закрывает голосование. Для большинства нужно 4 голоса при шести фракциях и 3 при четырёх. При отсутствии большинства во втором голосовании назначается берег с усилением фундамента.
2. В циклах 1–6 сначала проходят переговоры. Послы отправляют и принимают передачи, включая двусторонний обмен. Подтверждённые расходы резервируются и исполняются при переходе к планированию.
3. Лидер оплачивает целую единицу проекта либо вносит часть цены в общую единицу. Неполный набор ресурсов возвращается командам при закрытии цикла. Рабочие действия этого цикла затем сгорают. Ресурсную карточку оплачивает команда-получатель целой единицы. Получить помощь для неё можно передачей на переговорах.
4. После третьего цикла передайте роли. В циклах 4–6 у послов отдельные словари. После шестого цикла показывается состояние города для обсуждения.

Обычная сделка фиксирует передачу ресурсов в текущем цикле. В варианте `negotiation` послы также могут оформить компенсацию за отказ от вклада в городской проект. Ожидаемый исход проекта и три поля стоимости берутся из текущих карточек. [Сборка сценария](../swarm_work/c1_integration/integrated.md)

## Пробы экономики

По умолчанию действует базовый вариант. До запуска новой партии можно выбрать одно изменение:

| `GAME_EXPERIMENT` | Изменение |
| --- | --- |
| `baseline` | Исходные цены и поступления |
| `dry-yard` | Готовый Сухой двор дополнительно уменьшает стоимость каждой единицы защиты дворов на 1 рабочее действие |
| `stone-repair` | Ремонт причала стоит 0 древесины, 2 камня и 3 рабочих действия |
| `less-stone` | Базовое поступление камня у строителей уменьшается с 2 до 1, стартовый запас сохраняется |
| `negotiation` | С 5-го цикла доступна компенсация за отказ от вклада в грузовой двор или набережную. В 6-м цикле прежний караван заменён срочным заказом Торговцев |

Например, выполните `$env:GAME_EXPERIMENT='dry-yard'` перед командой запуска. Для возврата к базовой экономике задайте `$env:GAME_EXPERIMENT='baseline'`. Числовые сравнения на тех же действиях команд приведены в [отчёте](../swarm_work/c2_balance/resource_experiments.md).

### Репетиция переговоров

1. В 5-м цикле Жители предлагают Строителям компенсацию за отказ от вклада в грузовой двор. Например, одно рабочее действие даёт Строителям дополнительную возможность вложиться в каркас. После принятия компенсация зарезервирована, передаётся при закрытии переговоров, а Строители до конца цикла не могут оплатить даже часть грузового двора. Остальные команды могут достроить двор своей коалицией. На следующий цикл ограничение снимается. Единица грузового двора в этом варианте требует на одно рабочее действие больше, поэтому Торговцам приходится искать помощников.
2. В 6-м цикле Торговцы могут закрыть одну единицу последнего заказа за 1 древесину, 2 камня и 5 рабочих действий. Во вводной на другом берегу с представительством у Торговцев есть 2 рабочих действия. Строители или Жители могут передать недостающие три, а Торговцы предлагают за них свои ресурсы. Заказ оформляет лидер Торговцев. Успех даёт +3 благополучия Торговцам и +1 Строителям. После этого цикла окно закрывается.

Команда сама решает, устроят ли её цена и упущенные вложения. Проверка двух полных базовых сценариев, запрета на повторную компенсацию, двух маршрутов закрытия заказа и истечения срока: `node site_app/check.mjs`.
